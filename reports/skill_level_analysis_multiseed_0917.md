# 多训练 seed 的 skill-level condition 分析

> 整理日期：2026-09-21（RGB-D aligned 第三 seed 同步）<br>
> 对应主实验登记：显式 condition 使用 3 个训练 checkpoint；RGB-D 排除 original checkpoint，使用 `2026090701`、`2026090702`、`2026091701` 三组 checkpoint。<br>
> 旧版单/少 seed 分析保留在 [`multi_task_condition_eval_0610.md`](./multi_task_condition_eval_0610.md)，本文件不覆盖旧文档。

## 1. 分析目标与数据范围

长时程家具拼装的 task success 同时受多个连续阶段影响，无法说明一个 condition 的收益来自哪个操作。本文沿用旧版 skill-level analysis 的统计和画图逻辑：先按完整语义标签计算条件完成率 `C/R`，再在同一 task 或跨 task 合并同类 Push、Pick、Place、Insert、Screw 的完成数与到达数。每个 rollout 内同一完整标签最多计一次；一条 rollout 可以贡献多个 Pick/Place 标签，因此相应分母可以超过 rollout 数。

原分析使用 `66` 份 task JSON；本轮加入 `2026091701` RGB-D 的 3 份 aligned JSON，共 `69` 份。`RGB-D+skill`、`RGB-D+colored GP (TAGPoint)`、`RGB-D+GP+skill`、`RGB-D+grasp` 和 `RGB-D+colored grasp` 各合并一个原始 checkpoint 与两个 supplemental checkpoint；plain GP 沿用三个原始 checkpoint。RGB-D 的 original checkpoint 因错误 data/checkpoint lineage 被排除，使用三个有效 checkpoint，每个 checkpoint/task 有 36 条 rollout，因此 RGB-D 也为 108 rollout/task。RGB 的 skill-level 表仍保留既有两 seed，因本轮论文对照只重算 RGB-D baseline。

Supplemental JSON 统一来自 aligned wrist、positive-meters depth（RGB 除外）、scripted annotation 与 reward-only endpoint success 的复测。原始非 grasp checkpoint 沿用旧版 0610 main JSON；原始 grasp checkpoint 沿用旧版已经核验的 fresh36 clean-n0 JSON，而不重新引入七月 policy-input 不确定批次。由于 original 与 supplemental 的评测输入契约并非完全一致，本分析用于阶段定位，不将 pooled 差值解释为严格的 train-seed 因果效应。

### 统计口径

- 主表和两张图报告 `100 × ΣC/ΣR`，不是不同 seed 百分比的平均。
- `reports/data/skill_level_multiseed/seed_skill_type.csv` 同时保存逐训练 seed 的比例；`cross_task_skill_type.csv` 保存 pooled 比例及 seed mean/sample std，便于后续改成带误差条版本。
- `—` 表示没有 rollout 到达该阶段，不是 0% 成功率。
- Assembly annotation 只作为诊断字段，不替代 evaluator 的完整任务成功判定。

## 6. 更新后的数据观察

### 6.1 多 seed 后，旧版 Push/Pick 增益不再成立

三 seed RGB-D 基线在跨任务 Push 与 Pick 上已经达到 `98.15%` 和 `98.12%`。相对 RGB-D，plain GP 的 Push/Pick 变化为 `+1.23/-2.12 pp`，skill-only 为 `-1.23/-1.80 pp`，GP+skill 为 `-0.62/-1.26 pp`。因此，本轮数据不再支持“condition 的收益主要集中于 Push/Pick”；更准确的描述是，这些早期阶段在新 RGB-D checkpoint 上接近饱和，condition 的可见差异主要转移到后续阶段。

### 6.2 Place 是最一致的正向差异

跨任务 pooled Place 在 RGB-D 下为 `77.78%`。plain GP、TAGPoint 与 GP+skill 分别达到 `83.84%`、`80.15%` 和 `86.99%`，对应 `+6.06`、`+2.37` 和 `+9.21 pp`。skill-only 为 `77.12%`，与 RGB-D 基本持平（`-0.66 pp`）。这与“已有阶段身份后，额外空间 point 主要帮助目标放置”的机制解释一致。

在四个完整 Place 标签上，GP+skill 相对 skill-only 的差值均为正：one-leg leg placement `+5.07 pp`、round-table leg placement `+4.99 pp`、round-table base placement `+12.07 pp`、lamp bulb placement `+18.10 pp`。lamp 仍给出最大的增量，但幅度从旧版的 `+23.57 pp` 更新为 `+18.10 pp`。

### 6.3 Insert 接近饱和，Screw 的方向依赖 condition

所有主 condition 的 Insert pooled C/R 均接近 97–100%，继续不把它解释为 condition 的独立优势：只有完成较严格 Place 的 rollout 才会进入 Insert。Screw 则没有一致的正向排序；相对 RGB-D，plain GP 为 `-13.83 pp`，skill-only 为 `-0.73 pp`，TAGPoint 为 `-3.31 pp`，GP+skill 为 `-4.03 pp`。GP 的 Screw 降幅主要见于 round-table：RGB-D 为 `138/142=97.18%`，GP 为 `114/144=79.17%`；其中第一个 Screw stage 分别为 `79/79` 与 `69/88`。one-leg 分别为 `96/98=97.96%` 与 `88/94=93.62%`，lamp 为 `35/52=67.31%` 与 `36/66=54.55%`。这与“二维点指定接触位置，但不单独指定旋转接触过程”一致，可作为机制假设；不同 policy 进入 Screw 时的状态及 checkpoint lineage 未匹配，不能据此认定 GP 导致独立 Screw 能力退化。

## 8. 旧版结论暂存与一致性检查

按当前写作要求，旧版定性结论先保留为待审文本：

> 两类 condition 的收益并不是各步骤的普遍、均匀提升，而是在跨任务汇总中最集中于 Push 和 Pick。GP 和 skill 都可能帮助 policy 区分当前任务或操作阶段；在已有 skill 信息时，加入 GP 的额外收益主要集中于 Place。Insert 的高 C/R 主要反映阶段入口筛选，Screw 没有一致提升。不同家具的收益分布并不相同，skill-level C/R 也不等同于固定入口状态下的独立 skill 能力。

其中后四句仍与新版数据兼容；第一句已被两组新 RGB-D checkpoint 改变，不能继续作为论文当前结论。论文正文应改为：**新 RGB-D checkpoint 已使 Push/Pick 接近饱和，空间 point 的主要正向差异集中于 Place，而 Screw 仍呈任务与 condition 依赖。**

## 9. 解释边界与后续检查

1. 本分析比较的是 policy 从任务起点运行后形成的阶段入口分布，不是将每个 policy 放到同一物理入口状态的独立 skill benchmark。
2. pooled `ΣC/ΣR` 会按实际到达数加权；逐 seed 比例和 sample std 已保存在机器可读表中，但本轮为了复现旧图逻辑没有绘制误差条。
3. 图 1 中 RGB-D 与三个 conditional baseline 都是 `n_train=3`，但第三 RGB-D seed 没有匹配 conditional run；等样本量不等于 paired 对照。RGB 的详细 skill-level 表在本轮仍保留两 seed。
4. Original 与 supplemental checkpoint 存在数据和评测契约差异。本文可以用这些结果定位阶段瓶颈，但不能把差值完全归因于 condition 本身。
5. 更严格的下一步是 matched-entry-state skill evaluation，或至少对训练 seed 级比例作 bootstrap/层级模型分析。
